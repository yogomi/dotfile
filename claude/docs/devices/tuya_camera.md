## フォルダ構成

SDカードをマウントすると以下の階層で録画が蓄積される。

```
<デバイスID>/
└── record/
    └── YYYY/
        └── MM/
            └── DD/
                ├── YYYYMMDD.index      # 1日1ファイルのシークインデックス
                └── HH/
                    └── HHMMSS.data     # 映像本体（1時間単位）
```

- `HH` はその時間帯の開始時刻（ほぼ `HH0000.data`）
- 最後のファイルは録画停止時刻で終わるため、1時間未満の場合がある

---

## .data ファイルの正体

**生のH.264 Annex Bストリーム**（コンテナなし）。

| 項目 | 値 |
|------|-----|
| コーデック | H.264 High Profile |
| 解像度 | 1280×720（720p） |
| フレームレート | 25 fps |
| 音声 | なし |
| タイムスタンプ | なし（パケットにPTS/DTS未設定） |
| ファイルサイズ目安 | 約200MB／1時間 |

ffmpegはこのファイルを **そのまま `h264` フォーマットとして認識する**（拡張子無関係）。

---

## .index ファイルの構造

バイナリ形式。先頭にカメラ内SDカードのフルパス文字列を含む。

```
例: /mnt/mmc01/SDT/057456529/record/2026/05/12/23/231254.data
```

その後、16バイト単位でキーフレームのエントリが続く。

| オフセット | サイズ | 内容 |
|-----------|--------|------|
| 0x00 | 4バイト | Unixタイムスタンプ（LE） |
| 0x04 | 4バイト | 不明（フラグ類？） |
| 0x08 | 4バイト | .dataファイル内のバイトオフセット（LE） |
| 0x0C | 4バイト | 不明（サイズ？） |

## MP4への変換方法

### 注意点

- `-c:v copy` では **タイムスタンプが設定されず2秒しか再生されない** 問題が起きる
- `setpts=N/25/TB` フィルタでフレーム番号からPTSを生成する必要がある
- 再エンコードが必要だが、`ultrafast` + `crf 18` で品質を保ちつつ高速変換できる

### 単一ファイルの変換

```bash
ffmpeg -y \
  -i input.data \
  -vf "setpts=N/25/TB" \
  -c:v libx264 -preset ultrafast -crf 18 -an \
  output.mp4
```

### 全ファイルの一括変換（日付プレフィックス付き）

```bash
OUT=/path/to/output  # 出力先ディレクトリ

find /path/to/デバイスID/record -name "*.data" | sort | while IFS= read -r f; do
  date_part=$(echo "$f" | grep -oE '[0-9]{4}/[0-9]{2}/[0-9]{2}' | tr -d '/')
  base=$(basename "$f" .data)
  out_file="${OUT}/${date_part}_${base}.mp4"
  echo "Converting: $f"
  ffmpeg -y \
    -i "$f" \
    -vf "setpts=N/25/TB" \
    -c:v libx264 -preset ultrafast -crf 18 -an \
    "$out_file" 2>&1 | grep "time=" | tail -1
done
```

出力ファイル名の例：`20260513_000000.mp4`

### 処理速度の目安（MacBook Air M2）

| ファイルサイズ | 映像時間 | 変換時間 |
|--------------|---------|---------|
| 約200MB | 約1時間 | 約85秒 |
| 約58MB | 約18分 | 約24秒 |

### MP4の再生時間表示について

`setpts=N/25/TB` で変換したMP4は、プレイヤーが表示する再生時間が実際の収録時間より短くなる（1時間分の映像が約40分と表示される）。これはフレーム数 × フレーム間隔で算出したタイムスタンプが実時間と一致しないためで、MP4の再生時間表示は信頼できない。映像内に焼き込まれたタイムスタンプ（左上）が実時間の正確な参照になる。
