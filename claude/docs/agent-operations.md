# Claude Code サブエージェント運用方針

## 基本方針

メインセッション（オーケストレーター）のコンテキストを綺麗に保つことを最優先とする。
判断はメインセッションに集約し、手を動かす作業・コンテキストを汚す作業を外に出す。

## 構成

| 役割 | 担当 | 用途 |
|------|------|------|
| オーケストレーター | メインセッション | 計画・タスク分解・設計判断・結果の統合 |
| 実装担当 | `implementer`（Sonnet） | 仕様が確定した実装・テスト作成・機械的な修正 |
| 調査担当 | `Explore`（標準搭載） | コードベースの横断調査。結論だけ受け取る |
| デバッグ調査 | general-purpose（モデル都度指定） | 原因調査を委譲し、仮説と根拠だけ受け取る |
| セカンドオピニオン | Claude の別モデル（新規コンテキスト） | 重要な設計判断の前、大きめの diff のレビュー |

## 委譲の判断基準

**委譲する：**

- 複数ファイルにまたがる機械的な修正、テスト一式の作成（→ implementer）
- 「どこで実装されているか」等の横断調査（→ Explore）
- ログやスタックトレースを大量に読む原因調査（→ general-purpose）

**メインセッションで直接やる：**

- 設計判断・技術選定（ユーザーとの対話で決める。サブエージェントには委譲しない）
- 数行の修正、1〜2ファイルで完結する変更
- 対話しながら方針を詰める作業

## セカンドオピニオン（Claude 内で完結）

- general-purpose サブエージェントをメインセッションと異なるモデル（Opus 等）で起動し、
  会話の経緯を含めない新規コンテキストでレビューさせる
- 価値の本質は「会話の文脈に染まっていない目」であり、コンテキストの分離で担保する
- Claude 側から自発的に呼ぶ条件は CLAUDE.md に記載
  （設計判断の提示前・100行を超える diff のレビュー）
- 確実に聞きたい場面では「セカンドオピニオンも取って」と明示指示する
- 外部AIサービス（Gemini / Antigravity 等）にはコードを渡さない
  - 個人向け無料枠はプロンプトとコードが収集され、モデル学習に利用されるため
  - Gemini CLI の個人向け無料枠は 2026-06-18 にサービス終了済み
  - 業務コードを外部サービスに送る場合は、会社のセキュリティポリシー確認が前提
- 意見は判断材料の一つ。最終判断は Claude とユーザーで行う

## コンテキスト衛生

- 話題の切れ目で Claude 側から「要点をファイルに逃して /clear・/compact」を提案する
  （CLAUDE.md に記載）
- 調査結果の生ログをメインセッションに持ち込まない
- 定型ルールは CLAUDE.md・rules・スキルに逃がし、毎回の指示を短くする

## 拡張の方針

- エージェントを増やすのは「同じ委譲パターンを3回以上手で書いた」と感じてから
- 役割固定のエージェント追加より、Agent 呼び出し時のモデル都度指定を優先する
- 利用枠の消費が実際に問題になった時点で構成を再検討する
